# Security Policy

## Supported Versions

Security fixes are provided for the 1.x branch. Older versions are no longer
supported.

## Reporting a Vulnerability

If you think that you have found a security issue,
don’t use the bug tracker and don’t publish it publicly.
Report it privately via a
[GitHub private vulnerability report](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability#privately-reporting-a-security-vulnerability)
or by email to <security@opendxp.io>.

We acknowledge receipt within 72 hours and keep you informed until a fix is
released. Please give us reasonable time to publish a patch before disclosing
the issue publicly.

Where the EU Cyber Resilience Act applies, we may be required to report actively
exploited vulnerabilities to the competent authorities. This does not replace the
coordinated disclosure process described here.

## Resolving Process

Every submitted security issue is handled with top priority by following these
steps:

1. Confirm the vulnerability
2. Determine the severity
3. Contact reporter
4. Work on a patch
5. Get a CVE identification number (may be done by the reporter or a security service provider)
6. Patch reviewing
7. Tagging a new release for supported versions
8. Publish security announcement
